# Model evaluation benchmarks

These benchmarks evaluate whether protein embeddings improve TE prediction when
related proteins or selected biological functions are held out of model training.
They use the `data/processed/input.pkl.gz` generated by the [main pipeline](../README.md#prepare-the-input).

Two workflows are provided:

| Workflow | Partitions | Models | Full run count |
| --- | --- | --- | --- |
| `protein` | c50, c70, c90; 10 seeds each | mRNA-only, mRNA + T5u, T5u-only | 90 |
| `function` | Six functional holdouts; 10 seeds each | mRNA-only, mRNA + T5u | 120 |

All commands below are run from the repository root.

## Validate the input

```bash
pip install -r benchmarks/requirements.txt
python benchmarks/scripts/validate_benchmarks.py --input data/processed/input.pkl.gz
```

The validator checks 9,926 versioned transcript IDs, the order of 78 tissue labels,
feature shapes, target masks, the checksums of the supplied benchmark data, and
all 90 partition files. It verifies that clusters do not cross subset boundaries
and that held-out functional classes are absent from training and validation.

Use `--strict-hashes` for an optional byte-for-byte comparison of `oht`, `TE`,
`y_mask` and `emb_T5u` with the reference input. Dtype or model execution
environment differences may change hashes even if the input schema is valid.
Loading the compressed pickle requires memory for the uncompressed arrays.
Only load trusted pickle files generated by the pipeline.

## Protein sequence similarity benchmark

```bash
# Preview the commands without loading the input or training.
python benchmarks/scripts/run_benchmarks.py protein --dry-run

# Train all three model conditions on all three thresholds and ten seeds.
python benchmarks/scripts/run_benchmarks.py protein --device cuda
```

The three clusterings were independently generated with CD-HIT 4.8.1 using global
sequence identity thresholds of 50%, 70% and 90%. They contain 8,624, 9,502 and
9,843 clusters, respectively. Entire clusters are assigned to train, validation
and test with target proportions of 0.6, 0.2 and 0.2. Models use matched splits.

These are CD-HIT clustering thresholds; they do not guarantee a maximum pairwise
identity between every pair of proteins in different partitions. The clustering
used `-G 1 -d 0`, `-n 3` for c50, and `-n 5` for c70/c90, with no additional
minimum alignment-coverage threshold.

## Leave-one-function-out benchmark

```bash
python benchmarks/scripts/run_benchmarks.py function --device cuda
```

| GO category | Identifier |
| --- | --- |
| Ribosome | GO:0005840 |
| Plasma membrane | GO:0005886 |
| Extracellular region | GO:0005576 |
| Mitochondrion | GO:0005739 |
| Immune system process | GO:0002376 |
| RNA binding | GO:0003723 |

For each category, all annotated cohort members form the test set. Other proteins
in the same c50 clusters as test proteins are excluded entirely. The remaining
clusters are split into train and validation with target proportions of 0.75 and
0.25. The test set stays fixed across seeds; training/validation assignment varies.
Functional categories can overlap with one another.

The fixed splits are ready to use: no GO download or additional embedding
calculation is required. Transcript IDs omitted from a functional split are the
intentionally excluded c50 neighbors.

## Select runs and manage outputs

For example, run only mRNA + T5u on c50 with seed 0:

```bash
python benchmarks/scripts/run_benchmarks.py protein --groups c50 --conditions mrna_t5u --seeds 0 --device cuda
```

- `--input`: alternate path to a generated `input.pkl.gz`.
- `--output`: fresh output directory; defaults to `benchmarks/runs/protein_cluster_baseline` or `benchmarks/runs/go_slim_holdout`.
- `--groups`: `c50 c70 c90` for protein; category IDs such as `GO_0005840` for function.
- `--conditions`: `mrna_only`, `mrna_t5u`, and (protein only) `t5u_only`.
- `--seeds`: distinct values from 0 to 9.
- `--device`: `cuda`, `cpu`, `mps` or `auto`. Full CPU training is slow.
- `--save-checkpoints`: save model weights locally. By default the benchmark runner does not save checkpoints.
- `--epochs`: defaults to 100. Shorter runs are useful for development but are not comparable to the reference experiment.

Each run writes `command.json`, `stdout.txt`, `stderr.txt`, `class_used.txt` and
`metrics.tsv`. Existing run directories are rejected to prevent overwriting.
For retries, use a fresh output directory. When scheduling subsets separately,
select disjoint groups, conditions or seeds. Run outputs and checkpoints are
ignored by Git.

## Summarize and plot results

For external validation against user-downloaded Table EV3, see [PTR.md](PTR.md).
Its figure workflow uses reference prediction medians and does not require
checkpoints or embedding generation.


To recreate the primary model comparison figure (`FigMain`) from the included
reference metrics, run `python benchmarks/scripts/plot_main_comparison.py`. See
[FIGURES.md](FIGURES.md) for its inputs, outputs and statistical annotations.


After the complete runs finish:

```bash
python benchmarks/scripts/summarize_protein_cluster_baseline_t5u.py benchmarks/runs/protein_cluster_baseline benchmarks/results/protein_cluster_baseline
python benchmarks/scripts/summarize_go_slim_holdout.py benchmarks/runs/go_slim_holdout benchmarks/results/go_slim_holdout
python benchmarks/scripts/plot_benchmark_overview.py --results benchmarks/results --output benchmarks/results/figures
```

These commands plot an overview of your own two benchmark runs, including
T5u-only. To recreate the paper's **three-panel robustness figures**, use the
reference-data workflow in the [main README](../README.md#recreate-tables-and-figures-from-reference-results-no-gpu-required), or draw directly from the supplied summaries:

```bash
python benchmarks/scripts/plot_benchmarks.py --output benchmarks/results/figures
```

This creates `FigRob` (Pearson) and `SFigRob_spearman`, with panels for protein
similarity, c50 controls and functional holdouts. The included control-summary
TSVs support figure recreation only; the benchmark training runner does not
rerun random/shuffled encoder or other control experiments.

The optional `plot_benchmark_overview.py` requires both benchmark summaries and
all ten seeds. It creates `benchmarks_pearson.png/.pdf` and
`benchmarks_spearman.png/.pdf`, which are overview figures, not the paper layout.
Recreating statistics from supplied metrics does not regenerate predictions.
See [FIGURES.md](FIGURES.md) for the paper figure inputs and panel definitions.

## Model and statistical settings

Training uses Adam with learning rate 1e-4, batch size 100, 100 epochs, masked MAE
loss and selection of the epoch with the lowest validation MAE. Pretrained T5u
embeddings remain fixed. T5u-only zeros the mRNA representation while retaining
the downstream model architecture; mRNA-only uses no protein embedding.

Pearson and Spearman correlations are calculated separately for each tissue and
averaged within each run. Tests compare matched run means. The protein summary
reports paired t-tests and Wilcoxon tests; the exact comparisons and adjusted
values are in `overall_comparisons.tsv`. For functional holdouts, the six paired
t-tests are Holm-adjusted separately for Pearson and Spearman. Repeated splits
are not independent biological replicates. Hardware and software differences
can affect training results; bitwise reproduction is not guaranteed.

## Data provenance and partition regeneration

The metadata contains transcript/gene IDs, cluster assignments and selected GO
memberships, with no protein sequences or raw TE measurements. GO resources use
the 2026-06-19 release; Ensembl BioMart annotations were retrieved on 2026-08-26.
GO slim mapping propagated `is_a`, `part_of`, `regulates`, `positively_regulates`
and `negatively_regulates` relations. Only the six selected classes are included.
See [Gene Ontology](https://geneontology.org/) and
[Ensembl BioMart](https://www.ensembl.org/biomart/martview) for the upstream
resources and their terms.

Keep the supplied split files and within-subset ID order when comparing with
reference results. Regenerating annotations against newer releases changes the
benchmark. To reconstruct the functional partitions from the included metadata:

```bash
python benchmarks/scripts/make_go_slim_holdout_splits.py benchmarks/metadata/cohort.tsv benchmarks/metadata/protein_cluster_membership.tsv benchmarks/metadata/gene_go_slim_membership.tsv /tmp/aaemb-function-splits
```

`metadata/input_reference.json` records reference input hashes, and
`metadata/checksums.json` records benchmark data checksums. See the
[testing guide](TESTING.md) for validation commands and verification coverage.
