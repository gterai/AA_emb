# Revision analyses from `input.pkl.gz`

This workflow reproduces training and evaluation on fixed protein-cluster
partitions (c50/c70/c90) and six leave-one-function-out partitions. It starts
from the input generated by the existing repository pipeline. Embeddings,
trained checkpoints, raw measurements and sequences are not distributed here.
Models and source data are obtained by each user through the existing pipeline.

## 1. Generate the input and install analysis dependencies

Follow the root README to obtain the external Excel table, install PyTorch and
run `bash scripts/1_embed.sh` followed by `bash scripts/2_prep.sh`. From the
repository root, install the additional plotting dependencies:

```bash
pip install -r revision/requirements.txt
python revision/scripts/validate_revision.py --input data/processed/input.pkl.gz
```

The validator checks 9,926 versioned transcript IDs, 78 tissue labels in their
original order, feature shapes, target masks, all 90 split files, c50 exclusions
and cluster/function leakage. Input loading requires enough RAM for the
uncompressed arrays; the compressed file size is not a memory estimate.
Use only input pickle files you generated or otherwise trust.

Optional `--strict-hashes` compares the mRNA arrays, TE values, masks and T5u
embeddings byte-for-byte with the revision reference. Different dtype or pLM
execution environments can change these hashes without invalidating the schema.

## 2. Train and evaluate

```bash
# Inspect the 90 protein-cluster commands without training or loading input.
python revision/scripts/run_revision.py protein --dry-run

# c50/c70/c90 x mRNA-only/mRNA+T5u/T5u-only x seeds 0..9 (90 runs).
python revision/scripts/run_revision.py protein --device cuda

# Six functions x mRNA-only/mRNA+T5u x seeds 0..9 (120 runs).
python revision/scripts/run_revision.py function --device cuda
```

Both commands default to `data/processed/input.pkl.gz`. An alternate input can
be supplied with `--input /path/to/input.pkl.gz`. The runner checks the input
before starting and retains commands, logs, metrics and the actual split used.
Checkpoints are not saved unless `--save-checkpoints` is specified; all local
run outputs are ignored by Git. Existing run directories are rejected to avoid
overwriting results. For a retry, choose a fresh `--output` directory.

To run a selected subset, for example one c50 run:

```bash
python revision/scripts/run_revision.py protein --groups c50 --conditions mrna_t5u --seeds 0 --device cuda
```

Use distinct/unrun subsets or a fresh output directory when mixing subset and
full runs. `--epochs` defaults to 100; shorter runs are development checks and
must not be interpreted as reproduction of the published results. `--device`
supports cuda, cpu, mps and auto. CPU training is possible but slow. Numerical
identity across GPU/software environments is not guaranteed.

## 3. Aggregate and plot

After all default runs have completed:

```bash
python revision/scripts/summarize_protein_cluster_baseline_t5u.py revision/runs/protein_cluster_baseline revision/results/protein_cluster_baseline
python revision/scripts/summarize_go_slim_holdout.py revision/runs/go_slim_holdout revision/results/go_slim_holdout
python revision/scripts/plot_revision.py --results revision/results --output revision/results/figures
```

For a quick reproduction of the original statistics without embeddings, model
weights or any training, use the published per-tissue reference metrics:

```bash
python revision/scripts/summarize_protein_cluster_baseline_t5u.py revision/reference_metrics/protein_cluster_baseline revision/results/protein_cluster_baseline
python revision/scripts/summarize_go_slim_holdout.py revision/reference_metrics/go_slim_holdout revision/results/go_slim_holdout
python revision/scripts/plot_revision.py --results revision/results --output revision/results/figures
```

The latter reproduces aggregation and visualization, not model predictions.
`reference_results/` contains the expected summary tables. The new figures show
the public subset of experiments rather than reproducing the entire manuscript
figure layout. Dots are individual run means; error bars are mean +/- sample SD.

## Design and provenance

- Protein partitions: independent CD-HIT 4.8.1 clustering at global identity
  0.50, 0.70 and 0.90, with `-n 3`, `-n 5` and `-n 5`, respectively, and
  `-G 1 -d 0`. No additional alignment-coverage threshold was imposed.
  c50/c70/c90 contain 8,624/9,502/9,843 clusters. Whole clusters were assigned
  with target train/validation/test fractions 0.6/0.2/0.2. These labels are
  clustering thresholds, not a guarantee of a maximum pairwise identity
  between every pair of proteins in different partitions.
- Functional holdouts: ribosome (GO:0005840), plasma membrane (GO:0005886),
  extracellular region (GO:0005576), mitochondrion (GO:0005739), immune system
  process (GO:0002376), and RNA binding (GO:0003723). Every annotated cohort
  member is held out. Other members of its c50 clusters are excluded entirely;
  the remaining clusters are split 0.75/0.25 for train/validation. The test
  membership is fixed across seeds; classes can overlap with each other.
- GO resources: 2026-06-19 release; Ensembl BioMart annotations retrieved
  2026-08-26. The original GO slim mapping propagated `is_a`, `part_of`,
  `regulates`, `positively_regulates` and `negatively_regulates` relations.
  The metadata table retains only the six selected categories.
  Sources: https://geneontology.org/ and https://www.ensembl.org/biomart/martview
  (derived annotation data retain their upstream terms and attribution).
- Fixed split files preserve the ID order used in the revision runs. Do not
  regenerate them against a newer GO release when comparing reference results.
  `metadata/cohort.tsv` contains ID mappings only, with no protein sequences.
  IDs absent from a functional split are intentionally excluded c50 neighbors.
- Optional functional split regeneration (GO downloads are not needed):

```bash
python revision/scripts/make_go_slim_holdout_splits.py revision/metadata/cohort.tsv revision/metadata/protein_cluster_membership.tsv revision/metadata/gene_go_slim_membership.tsv /tmp/aaemb-regenerated-function-splits
```

- Training preserves the revision implementation: **Adam**, learning rate
  1e-4, batch size 100, 100 epochs, masked MAE, validation-MAE model selection.
  An available manuscript draft says AdamW; that wording differs from the
  evaluated code. We retain Adam for continuity with the reference results.
- T5u-only uses `--abl_type m`: the mRNA representation is zeroed while the
  downstream architecture is retained. mRNA-only uses no protein embedding.
- Pearson/Spearman correlations are computed for each tissue, then averaged
  within each run. Paired tests use matched seeds. The protein summarizer
  retains the original comparison families and reports additional Wilcoxon
  results; consult `overall_comparisons.tsv` for comparisons. In the functional
  analysis, the six paired t-tests are Holm-adjusted separately for Pearson
  and Spearman. Repeated splits are not independent biological replicates.
- The original revision used an NVIDIA B200 environment. Local verification
  of the public workflow does not rerun all 210 GPU training jobs.

The two revision-specific input files used originally were checked against the
existing `input.pkl.gz`: cohort IDs, tissue order and hashes of `oht`, `TE`,
`y_mask`, and `emb_T5u` match. No revision-only embeddings are required here.
`metadata/input_reference.json` records reference feature hashes;
`metadata/checksums.json` records published data checksums.

## Scope

Included: protein similarity partitions and functional holdouts with the native
T5u model. Excluded: random/shuffled T5u, GO re-annotation against future releases,
external PTR validation and ESM-2 long-sequence sensitivity. The existing
embedding-generation and evaluation commands remain available in the main repo.
