# Public workflow verification (2026-09-08)

Base repository commit: `1271345`.

- All 90 published partitions passed checksum, ID, protein-cluster leakage and
  functional-holdout checks.
- All 210 source runs used identical membership and within-subset ID order to
  the published split files (the output writer groups rows by subset).
- All 60 functional partitions regenerated byte-for-byte from the reduced
  published metadata, without downloading GO or loading embeddings.
- Reaggregation of 210 reference per-tissue metric files reproduced all eight
  reference summary tables at relative tolerance 1e-9 / absolute tolerance 1e-12.
- Pearson and Spearman figures were generated; the Pearson layout was visually
  inspected. The figures use the same plotting layout.
- Four workflow tests passed, including run counts, T5u-only ablation, duplicate
  split ID rejection and refusal to overwrite existing runs.
- Each of mRNA-only, mRNA+T5u and T5u-only completed one CPU epoch on synthetic
  inputs, producing 78 finite Pearson/Spearman pairs. Synthetic data and local
  checkpoints are not included in the repository.
- Revision inputs `input_esm2_length_sensitivity.pkl.gz` and
  `input_protein_controls.pkl.gz` were checked against the existing input
  reference: versioned IDs, tissue order, and the full content hashes of `oht`,
  `TE`, `y_mask`, `emb_T5u` matched. The input validator with `--strict-hashes`
  also passed on the latter file. A fresh clone does not contain `input.pkl.gz`;
  users must generate it using the existing pipeline.

Verification environment: Python 3.12.13, NumPy 2.4.4, SciPy 1.17.1,
PyTorch 2.12.1, Matplotlib 3.10.8 on macOS (CPU smoke training).
This environment verifies execution and aggregation, not bitwise reproduction
of B200 GPU training. All 210 full training jobs and the pLM embedding generation
pipeline were not rerun as part of this publication update.

Run the lightweight regression checks from the repository root:

```bash
python -m unittest discover -s revision/tests -v
```
